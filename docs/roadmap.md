# Roadmap

## Now

- Complete and independently review `0.1.0-alpha.1`: package/skills/helpers/fixtures/CI, local install, Microsoft Learn startup, Azure MCP startup/read boundary, and exact-head PR evidence.
- `0.1.0-alpha.2`: harden onboarding from the first live repository rollout by
  closing source-disposition scope before conversion, binding progress claims
  to proof, and making personal-account GitHub setup capability-probed and
  readback-driven. Add one Microsoft-grounded conditional modular-monolith
  profile so selected repositories can retain a single deployment unit with
  explicit business-module, dependency, persistence, and evolution boundaries.

## Next

- `0.2.0-alpha.1`: exercise onboarding and plan-deliver-review on one materially different existing Azure repository; depends on accepted alpha bootstrap.
- `0.3.0-beta.1`: satisfy the beta gate across at least two different Azure repositories, a large feature catalog, both explanation routes, GitHub personal-account setup, and Azure read/approval-stop evidence.

## Later

- `1.0.0-rc.1`: validate reinstall/upgrade/recovery, representative UI/.NET/GitHub/Azure routes, and freeze the supported plugin contract.
- `1.0.0`: stable release after explicit owner acceptance, interruption recovery proof, and no known release blocker.

## Not planned

- Non-Azure universal workflow ownership.
- Multiple lifecycle plugins or a public skill for every concern.
- Hooks, background organizer state, generated dashboards, workflow databases, or vendored upstream documentation.
- Automatic PR merge or unapproved live Azure mutation.
