# Repository policy profile

Onboarding must settle and write these facts into root `AGENTS.md` and canonical documents:

- Azure-oriented evidence/intended target and supported environments;
- Windows/PowerShell workflow and canonical verification command;
- repository mode: `development` or `released`;
- version scheme/current version, maturity stage, release authority, and supported contracts;
- `Visual UI: present` or `absent`;
- source registry with content roles and mutation rules, including real protected roots;
- provided-material permission/licensing assumption and prohibition on unsolicited PII/DPA/DPIA/privacy/retention/licensing gates;
- repository-provided examples only; no synthetic domain materials;
- purpose-revealing names and user-facing language boundaries;
- mistake admission, append-only log, and read-only pending-entry behavior;
- path-aware Docs/Full verification and exact command;
- skill routes for onboard, plan, deliver, explain, review, and Azure operate.

Keep always-loaded instructions concise and operational. Put explanations, schemas, and detailed procedures in linked documents. Nested `AGENTS.md` files contain local deltas; they do not cancel root policy.

In development mode, replaced unreleased behavior is removed rather than supported through fallbacks/shims/aliases/dual paths. In released mode, compatibility exists only for a declared supported contract with owner, observable activation, proof, and removal criteria.
